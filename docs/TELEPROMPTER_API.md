# Human Teleprompter Script Generation

POST /api/v1/generation-jobs uses existing service authentication, organisation
binding and Idempotency-Key. New requests set schema_version=3,
operation=teleprompter_script, count=1 and script_options:

```json
{
  "source": "saved_topic",
  "topic": "Preparing for a clinic visit",
  "speaker": "",
  "language": "English",
  "target_seconds": 75
}
```

source can also be surprise; the worker chooses a context-grounded topic in that
case. The normal business, business_id, organisation binding, source_version and
public_facts contract remains. Research and GEO evidence follow existing policy.
Hyclinics resolves saved topic IDs; Reachly receives the authorized title as data.
The new operation rejects original media, static creative briefs and multiple
outputs. Absent script_options is omitted when serializing older operations,
preserving existing v1/v2 request digests and replay semantics.

Poll the existing job route. A completed result has operation=teleprompter_script,
prompt_version=teleprompter-script-v2, source_version, business_id and script:

- title: at most 200 characters.
- segments: 3-16 entries with text, cue, pause_seconds.
- cue: neutral, warm, reassuring, thoughtful, emphasis or smile.
- pause_seconds: 0-3; delivery tags are not allowed in spoken text.
- sources: supplied nonempty public-fact field names supporting the script.
- estimated_seconds and word_count: derived from text, not trusted model values.

Targets are 60, 75 or 90 seconds. Validation estimates 126 words/minute plus
pauses, with a 15-second target tolerance and 55-100 second outer bounds.
Speech cadence and languages vary; estimates are not a recording duration promise.
Malformed, unsupported-source or out-of-range output fails visibly; no fabricated
fallback and no extra paid repair call is made.

The Gemini script path opts into JSON Schema output (response_mime_type plus
response_json_schema), with exact fields, cue/source enums and bounds. Other
LLM operations retain their existing behavior. OpenAI/Anthropic retain their
existing text adapters and receive the same timing instructions and local checks.
The schema is not a substitute for local semantic/duration validation. The
prompt budgets spoken words separately from pauses for each selected duration.
The deployed google-genai 2.11.0 supports response_json_schema; use an SDK that
exposes this field. Reference: [Google Gen AI SDK](https://github.com/googleapis/python-genai).

HTTP 200 from the polling route confirms retrieval, not successful generation.
Inspect state, failed_stage and error_code. Script failures now include a fixed
error_code, and duration failures include numeric error_metrics (word_count,
estimated_seconds, target_seconds). Raw provider text/errors are never included
in these diagnostics. Codes are script_invalid_json, script_invalid_structure,
script_invalid_title, script_invalid_segments, script_invalid_spoken_text,
script_invalid_cue, script_duration_out_of_range, script_invalid_sources,
script_too_large, script_missing_facts and script_provider_error. Provider
failures require operator inspection before another paid request. No failed
job is automatically replayed, and no media is generated by script writing.

The planner borrows business grounding and duration planning from longform_video,
but does not execute that pipeline. No ElevenLabs, voice cloning, audio capture,
image/logo rendering, video generation or publishing is invoked. Credentials are
resolved from the existing operator-provisioned provider profile, not request data.

Deploy Reachly before the Hyclinics consumer. Tests cover contract validation,
text-only dispatch, malformed cues, sources, estimated duration and legacy payload
compatibility. Local cross-product browser QA uses deterministic LLM fixtures;
real provider quality and post-deploy acceptance remain separate gates.
